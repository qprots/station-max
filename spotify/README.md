# Spotify: голосовое управление и приглушение на Станции Макс

Host-side демон, который связывает ассистента OpenStation с приложением
**Spotify TV** на колонке. Он решает две проблемы, которые нельзя надёжно
решить скриптами на самом устройстве:

1. **Музыка мешает микрофону.** Как только ассистент начинает слушать, Spotify
   ставится на паузу. После ответа воспроизведение возвращается, но только если
   паузу поставил сам демон и пользователь не попросил остановить музыку.
2. **«Выключи музыку» больше не уходит в Яндекс Музыку.** Демон распознаёт
   музыкальные интенты в распознанном тексте и управляет активным источником
   (Spotify TV), а не тем плеером, который выбрал LLM.

## Почему демон на хосте, а не на колонке

Android убивает фоновые процессы, запущенные через `adb shell`, сразу после
закрытия adb-сессии. Именно поэтому on-device watcher'ы «жили» несколько секунд
и музыка не приглушалась. В station-max уже есть постоянные host-side сервисы
(OpenStation watcher, статический сервер), и этот контроллер устроен так же:
systemd-юнит на хосте, общение со станцией по HTTP и adb.

Ничего не устанавливается на устройство и не меняет `/system`, `/vendor`,
`/odm` или прошивку.

## Требования

- Станция с постоянным ADB (`adb connect <ip>:5555`).
- OpenStation с включённым ассистентом (Gemini или другой режим) и доступным
  `http://<ip>:8080/api/status`.
- Установленное приложение **Spotify TV** (`com.spotify.tv.android`) с
  авторизованным аккаунтом Premium.
- Python 3.8+ на хосте, `adb` в `PATH` (или путь через `--adb`).

## Установка

```bash
cd spotify
./install.sh --station http://192.168.10.219:8080 \
             --adb /path/to/adb \
             --serial 192.168.10.219:5555
```

Установщик раскладывает файлы в `~/.local/share/station-max-spotify`, пишет
`~/.config/station-max-spotify.env` (права `0600`) и включает user-сервис
`station-max-spotify.service`.

Проверка:

```bash
systemctl --user status station-max-spotify
journalctl --user -u station-max-spotify -f
curl -s http://127.0.0.1:8099/status | python3 -m json.tool
```

Диагностика без запуска демона:

```bash
python3 spotify_control.py --adb /path/to/adb --serial 192.168.10.219:5555 --once
```

Удаление:

```bash
./install.sh --uninstall
```

## Что делает демон

| Ситуация | Действие |
|---|---|
| Ассистент перешёл в `listening`/`thinking`/`speaking` | Spotify ставится на паузу (`KEYCODE_MEDIA_PAUSE`), если играл |
| Ассистент вернулся в `idle` | Spotify возобновляется, если паузу ставил демон |
| Пользователь сказал «выключи музыку», «стоп», «останови» | Spotify остаётся на паузе, автопродолжения нет |
| «Пауза» | Пауза без автопродолжения |
| «Продолжи», «включи музыку» | Возобновление, если Spotify был активен |
| «Следующий трек», «дальше» | Сначала возобновляет Spotify (он забирает аудиофокус), затем `KEYCODE_MEDIA_NEXT` |
| «Предыдущий», «назад» | Так же, затем `KEYCODE_MEDIA_PREVIOUS` |
| «Включи в Spotify <запрос>» | Поиск Spotify по запросу; TV-версия обычно сразу играет верхний результат |
| `spotify:track:...`, `open.spotify.com/...` | Детерминированный запуск через VIEW-intent |

Правила, которые защищают от «сама включилась»:

- демон помнит, **кто** поставил паузу: если музыку поставил пользователь,
  после ответа она не возобновляется;
- если в этот момент играет другой источник (например, Яндекс Музыка через
  `com.openstation.launcher`), Spotify не возобновляется;
- если Spotify не был активен последние `RESUME_WINDOW` секунд (по умолчанию
  300), команды «продолжи»/«дальше» его не трогают;
- команды про свет, телевизор, громкость, YouTube и таймеры игнорируются.

## Локальный API

Слушает только `127.0.0.1` (порт по умолчанию `8099`).

```bash
curl -s http://127.0.0.1:8099/status

curl -s -X POST http://127.0.0.1:8099/command \
     -H 'Content-Type: application/json' \
     -d '{"action":"pause"}'

curl -s -X POST http://127.0.0.1:8099/command \
     -H 'Content-Type: application/json' \
     -d '{"action":"play_uri","uri":"spotify:track:4uLU6hMCjMI75M1A2tKUQC"}'
```

Действия: `pause`, `stop`, `play`, `resume`, `next`, `previous`, `search`
(с полем `query`), `play_uri` (с полем `uri`).

## Ограничения

- **Произвольный поиск** («включи в Spotify …») открывает поиск Spotify и
  обычно запускает верхний результат. Выбор остаётся за Spotify TV; для
  гарантированного трека используйте `spotify:track:<id>` или ссылку
  `open.spotify.com` — они запускаются детерминированно.
- Ассистент по-прежнему может параллельно выполнить свою музыкальную команду
  (Яндекс Музыка). Для явных команд демон возвращает аудиофокус Spotify, но
  если нужен конкретный трек, надёжнее сказать «включи в Spotify …» или
  использовать ссылку.
- Демон управляет только Spotify TV. Яндекс Музыка остаётся зоной
  ответственности OpenStation; демон лишь не возобновляет Spotify поверх неё.
- Если хост (WSL) спит или adb-соединение потеряно, приглушение не сработает.
  Это осознанный компромисс: альтернатива — нативная правка приложения, для
  которой нужен Android SDK/NDK.
- Команды, произнесённые без wake word, демон не видит: он читает состояние
  ассистента, а не микрофон.

## Тесты

```bash
python3 -m unittest discover -s spotify/tests -v
```

Тесты не требуют устройства: транспорт подменяется фейком, время
инжектируется, поэтому проверяются именно правила паузы/возобновления и
разбор фраз.
